# Windows 定时关机工具

tkinter 小工具：分钟倒计时关机、指定时间关机、取消关机，任务持久化，重启程序自动恢复倒计时。

## 直接运行

```bash
python main.py
```

## 打包成 exe

```bash
pip install pyinstaller
pyinstaller -F -w --name "定时关机" --distpath . main.py
```

说明：

- `-F`：打包成单文件 exe
- `-w`：无控制台黑窗
- `--name "定时关机"`：生成的程序名为 `定时关机.exe`
- `--distpath .`：exe 直接输出到项目根目录（不生成 dist 文件夹）
- 可加 `--noconfirm`：覆盖旧文件时不再询问

打包会产生 `build\` 中间目录和 `定时关机.spec`，exe 正常运行不依赖它们，可随意删除。
重复打包时 PyInstaller 会复用缓存，速度更快；如打包异常可先删除 `build\` 目录再重新打包。

## 运行环境要求（分发到新电脑前必看）

`定时关机.exe` 是单文件自包含程序，拷过去双击即可，无需安装 Python 或 VC++ 运行库，也不需要管理员权限。

| 系统 | 能否运行 | 说明 |
| --- | --- | --- |
| Windows 11 x64 | ✅ | 正常 |
| Windows 10 x64（1809 及以上） | ✅ | 正常，UCRT 随系统提供 |
| Windows 10/11 ARM64 | ⚠️ | 靠系统 x64 模拟运行，一般可用，未实测 |
| Windows 8.1 / 8 | ❌ | 打包用的是 Python 3.14，官方只支持 Win10+ |
| Windows 7 | ❌ | 缺 `api-ms-win-core-path-l1-1-0.dll`，且 Python 3.14 不支持 |
| 32 位 Windows | ❌ | exe 为 64 位（x64） |

若必须支持 Windows 7，需用 Python 3.8 重新打包；支持 Windows 8.1 需用 Python 3.12（`main.py` 代码本身兼容这两版）。

新电脑上首次运行可能遇到：

- SmartScreen 提示"Windows 已保护你的电脑" → 点"更多信息" → "仍要运行"（exe 未做代码签名）。
- 杀软/公司 AppLocker 拦截 → 需加白名单（pyinstaller 单文件程序易被误报）。
- 单文件运行时会把自身解压到 `%TEMP%\_MEIxxxx`，该目录必须可写（一般账号都满足）。

## 任务保存位置

关机任务（目标时间）保存在当前用户的 AppData：`%APPDATA%\ScheduledShutdown\shutdown_task.json`。

- 不写注册表，也不在 exe 所在目录生成任何文件；路径属于当前用户，无需管理员权限。
- 文件内容形如 `{"target_time": "2026-11-09 07:30:00"}`，设置 / 恢复 / 取消 / 到点时自动读写与清理。
- 写入采用「先写 `.tmp` 再原子替换」，避免中途退出留下半截文件；文件损坏或时间已过期，启动时会自动清理。
- 卸载或想清空状态，直接删除 `ScheduledShutdown` 目录即可。

升级说明：旧版本把任务写在注册表 `HKCU\Software\ScheduledShutdown`，再早的版本写在 exe 同目录的 `shutdown_task.json`。新版本只迁移 exe 同目录的旧 json（读到后删除），**不再读取注册表**，所以注册表里的旧任务不会自动迁移（此前下发的系统 `shutdown` 命令仍然有效）。如需彻底清掉旧键值，可手动执行：

```bash
reg delete "HKCU\Software\ScheduledShutdown" /f
```

## 关于「注销被取消 / 计划的关闭已取消」通知

退出程序时系统里的计划关机命令是保留的。旧版每次启动恢复任务都会先执行 `shutdown /a` 取消旧命令，Windows 因此每次都弹一条系统通知。

现在恢复任务时**直接按剩余秒数重新下发**，不再取消：

- 系统里没有命令（例如刚重启过）→ 下发成功，重新设好；
- 系统里还挂着上次留下的命令 → `shutdown` 返回 1190，直接沿用旧命令，不执行 `/a`，不弹通知。

两条路径的关机时刻一致（`/t` 秒数都由同一个绝对目标时间算出）。只有**手动点「取消关机」或改任务**时才会执行 `shutdown /a`，那条通知是 Windows 自身行为。

## 已有任务时改时间

两个「开始」按钮共用 `set_shutdown_target()`，已有任务时是**直接改期**，不是删掉再重设：

- 新命令确认成功之前，`target_time`、`running`、AppData 任务文件都不动；成功后一次性提交并覆盖保存，全程不调用 `delete_saved_task()`。
- 失败时原任务原样保留（状态、文件、界面都不变），并尝试把旧的系统关机命令补回去，提示「修改关机时间失败，已保留原来的关机任务」。
- 先直接下发新时间；系统里没有挂着的关机命令时（重启后第一次设置）一次到位，不执行任何 `/a`。
- 重复点同一个时间（2 秒内）直接忽略，连点不会触发取消/重设。

注意：Windows 只允许同时存在一个 `shutdown /t` 计划关机，且**没有提供修改时间的接口**。因此当系统里确实挂着旧命令时，改时间仍必须先 `shutdown /a` 再重新下发（这一步会弹一条系统通知，无法屏蔽）。程序层面已经不再"删任务再重建"，但系统层面的这一次取消是 Windows 的限制。若需要连这条通知也彻底消失，只能换成 Windows 计划任务（`schtasks`）来承载关机时间——那是另一套机制，需要时再改。

## 开机自启

把 `定时关机.exe` 的快捷方式放到启动文件夹（Win+R 输入 `shell:startup` 打开）。
