# 闲鱼本地自动发货工具（Python 版）

在**自己的电脑上**运行，监控闲鱼网页版（goofish.com）的消息，当买家拍下并付款后（买家说"已拍/已付款"，或聊天里出现"买家已付款"系统消息），自动把该商品配置的**发货内容**（框里所有内容，支持多行，整段一条消息发出）发给买家。发货内容**不会消耗、不会删除**，同一商品可以反复使用，所以一卡一码的库存模式不再需要——你写什么就发什么。同一单只发一次。

## 目录结构

```
D:\Pdemo\闲鱼\
├── auto_delivery.py      入口（命令行工具）
├── app.py                自动发货主逻辑（轮询、识别、发送、WS 监听）
├── browser_session.py    浏览器持久化会话 + inspect 选择器检查
├── stores.py             发货内容读取 / 发货记录（本地文件存储）
├── admin_server.py       商品管理网页服务（本机 127.0.0.1:8765）
├── admin.html            商品管理网页页面
├── account_login.py      「＋ 新增账号」时弹出的扫码登录窗口
├── stop_all.py            停止所有正在运行的自动发货实例
├── 商品管理.bat          双击打开商品管理页面（账号的启动/停止都在页面里操作）
├── config.json           ★ 全局设置：触发词、页面选择器、轮询频率等
├── products.json         ★ 商品与发货内容（商品管理页面管理的就是它，所有账号共用）
├── accounts\            每个账号一个独立的浏览器登录档案（账号 = 一个沙盒）
├── data\                 运行时生成：已发货记录 delivered*.json、发货流水 used_cards*.log、
│                         正在运行的实例记账 data\.running\*.json
├── logs\                 运行时生成：每个账号一个日志 run_<账号>.log、inspect 报告与截图
└── browser_data\         默认账号的浏览器登录会话（扫码一次后免登录）
```

## 多账号并行（每个账号一个沙盒）

商品管理页「账号管理」里**每个账号都可以单独点「▶ 启动」／「■ 停止」**，也可以点「▶ 全部启动」／「■ 全部停止」。启动后每个账号各有一个自己的控制台窗口（标题是「自动发货 - 账号名」），**可以同时跑多个账号，互不影响**：

- 登录档案、发货去重记录、日志文件按账号分开，一个账号出错/停止不影响别人；
- 每个进程里**只看得见自己这个账号**（配置被收敛成只含自己），也**不会改「当前账号」**，所以谁先启动、谁后启动都不会抢别人的号；
- 同一账号（或同一登录档案目录）**不允许重复启动**，重复点会提示已在运行；
- 商品与发货内容仍是**所有账号共用**一份 `products.json`。

## 快速开始

> **日常使用：双击 `商品管理.bat` 打开商品管理页，在「账号管理」里对每个账号点「▶ 启动」即可**（会弹出控制台窗口 + 浏览器窗口；停止用「■ 停止」或「全部停止」，也可直接关掉控制台窗口）。下面的命令行方式和它效果相同。注意：一个浏览器登录档案同时只能被一个实例占用，同一账号重复启动会被自动挡掉。

```bash
# 1. 安装依赖（首次）
pip install -r requirements.txt
python -m playwright install chromium

# 2. 首次登录：会弹出浏览器，用手机闲鱼/淘宝扫码，登录后自动保存会话
python auto_delivery.py login

# 3. 配置商品（两种方式任选）：
#    a. 双击「商品管理.bat」，在网页里增删改商品/规格，发货内容直接填在商品里（推荐）
#    b. 手动改 products.json 的 products（发货内容写在各商品的 cards 字段，一整段字符串，可含换行）

# 4. 先用演练模式跑（config.json 里 dry_run=true：只打印"命中发货"，不真发）
python auto_delivery.py run

#    只跑某一个账号（可多个账号同时各开一个窗口，互不影响）
python auto_delivery.py run --account 账号名

# 5. 确认无误后，把 dry_run 改为 false，正式发货。保持浏览器窗口开着即可。
```

## 命令

| 命令 | 作用 |
|---|---|
| `python auto_delivery.py login [--account 账号名]` | 打开浏览器扫码登录，保存会话 |
| `python auto_delivery.py run [--account 账号名]` | 启动自动发货监听（Ctrl+C 停止）；带 `--account` 时只跑该账号，可多开 |
| `python auto_delivery.py inspect` | 检查页面元素并生成报告 + 截图（校准 config.json 的 selectors 用） |
| `python auto_delivery.py send-test --search 关键词 --text 内容` | 手动向指定会话发一条消息（真实发送，测试用） |
| `python auto_delivery.py cards` | 查看各商品/规格的发货内容是否已填写（字数、行数） |

## 配置说明（config.json）

- **商品管理页面**：双击 `商品管理.bat`，浏览器自动打开 `http://127.0.0.1:8765`（仅本机可访问）。可视化增删改商品：名字（填成闲鱼商品标题）、**发货内容（框里所有内容整段发送，可多行，发完不删除）**、发货话术、多规格（规格名+该规格的发货内容；按名称重合自动匹配），顶部可切换演练/正式模式。匹配按"商品名/规格名与订单文字重合的字数"自动认商品与规格，无需再填关键词。保存写回 `products.json` / `config.json`，**保存后重启自动发货生效**。
- **发货内容存储**：发货内容存在 `products.json` 各商品的 `cards` 字段里，是一整段文本（保留换行，可直接写多行链接/提取码/教程）。发货时把这段内容**原样整段**作为一条消息发出，**发送后不删除、不消耗**，同一商品可以反复卖、反复发；每次发货仍会写一行记录到 `data\used_cards.log`。旧版一行一卡的 `cards` 数组会在读取时自动拼成多行文本（内容不丢）。
- **账号管理**：商品管理页顶部有「账号管理」卡片。每个账号对应一个独立的浏览器登录档案（`config.json` 的 `accounts` / `current_account`，档案目录在 `accounts\账号名`）。**每个账号一行都有「▶ 启动」／「■ 停止」**，点启动就给这个账号单独开一个控制台窗口跑自动发货（可多个同时跑，各自独立沙盒，详见上面「多账号并行」）；正在运行的行会显示「运行中 · PID」。**「＋ 新增账号」**会立刻弹出一个独立的浏览器窗口（打开闲鱼登录页），用手机闲鱼/淘宝扫码登录；程序检测到已登录（读到 `unb` cookie）后，会自动把昵称/用户ID/登录时间记入账号列表并**切到该账号**（名字默认用昵称），页面自动刷新显示；登录失败/窗口被关则什么都不记录。「切换」即改用该号的登录态（重启自动发货生效）；「改名」只改本机备注名（登录档案、登录状态、已发记录都不变，去重记录会自动跟着改名）；每个账号后面会显示登录状态与真实昵称/ID，扫码登录成功后自动记录，之后启动免扫码；**启动自动发货时只要检测到已登录的账号，也会自动登记/更新到账号列表**（哪怕列表被删空、或当前账号没设置也会自动补一条），所以扫码登录后一定能在这里看到这个号；「删除」可从列表移除任意账号（**包括当前正在使用的**）：该账号的登录档案会被**彻底删除、不保留归档**（不可恢复，商品与发货内容不受影响）；删的是当前账号时，会自动切到剩下的第一个账号，一个都不剩则清空、下次启动重新扫码登录即可。若该账号的登录档案正被自动发货占用（删不掉），会提示先「停止自动发货」再删。**正在运行的账号不允许删除**，需先点「■ 停止」。账号的登录状态与真实昵称/ID 由登录时自动读取记录，页面不提供手动「识别账号」按钮。默认账号沿用 `browser_data`；去重记录按账号分开（`data\delivered.json` / `delivered.<账号>.json`），发货流水也按账号分开（`used_cards.log` / `used_cards.<账号>.log`），日志按账号分开（`logs\run_<账号>.log`），不同账号的同名买家不会互相干扰。商品与发货内容目前为所有账号共用。若页面顶部出现红色"后台还是旧版本"提示，说明有旧的「商品管理」窗口没关（两个服务抢同一端口），关掉全部只重开一个即可。
- **认单规则**：买家付款后，程序在所有已启用商品里，按"商品名称与订单/聊天文字重合的字符数"取最多的那个发货（商品名称越独特、与订单标题越一致越稳，无需单独填认单关键词）。
- `trigger_keywords`：触发发货的关键词。当前**只保留了 `买家已付款`**——只有聊天里出现"买家已付款"系统消息（买家完成付款）才会发货；买家发"已拍""我付款了"等普通聊天不会触发。
- `verify_system_notice`：默认 `false`。注意一个漏洞：如果买家**手动打字**"买家已付款"也会命中触发词。改为 `true` 后，发货前会进入聊天，按 `selectors.json` 里的 `system_notice_selectors` 查找"系统样式"的付款通知，找不到就不发。开启前请先用 `inspect` 确认选择器能命中，否则会一直跳过不发货。
- **多规格商品**（如颜色 白色/黑色，且发不同内容）：在商品里加 `variant_rules`，每条规则配**规格名**和各自的发货内容：
  ```json
  {
    "name": "手机壳",
    "cards": "默认发货内容第一行\n第二行",
    "variant_rules": [
      {"name": "白色", "cards": "白色专属内容\n第二行"},
      {"name": "黑色", "cards": "黑色专属内容"}
    ],
    "enabled": true,
    "reply_text": "感谢购买！您的卡密如下，请及时保存：\n{card}"
  }
  ```
  程序按"规格名与订单文字重合的字符数"取最多的规格发货（订单里"已选：白色"等字样对得上即认出）；**所有规格都没在订单文字里出现时走默认发货内容**。规格不同但发同一种货的话，不需要配 `variant_rules`。
- `products`：商品列表。`name` 是商品名称（填成闲鱼商品标题，用于自动匹配）；`cards` 是该商品的整段发货内容；`reply_text` 里的 `{card}` 会替换成这段内容，**没写 `{card}` 时程序会把内容自动附在话术后面**，`\n` 会被当成换行。
- `dry_run`：`true` 时只演练不发货；确认流程没问题后改成 `false`。
- `poll_interval_seconds`：轮询间隔；`send_delay_seconds`：发送前随机延迟（模拟人工，降低风控风险）。
- `headless`：保持 `false`（有界面更稳也更不容易被风控）。
- 其余参数一般不用动：`max_rows_per_poll`（每轮最多检查多少个会话）、`variant_gap_chars`（多规格"位置差"判定阈值，越大越保守）、`login_wait_seconds`（等扫码登录的时长）、`page_load_wait_ms`（页面加载等待）、`viewport`/`locale`/`timezone_id`（浏览器环境）、`send_delay_seconds`（发货前随机延迟范围，模拟人工）。

## 重要说明

1. **选择器可能需要一次性校准**：闲鱼网页改版后元素定位可能失效。运行 `python auto_delivery.py inspect`，打开 `logs\inspect_report.txt` 和截图，把报告里"命中 N 个"的选择器填回 `config.json` 的 `selectors` 部分即可，代码本身不用改。
2. **去重**：按"买家+商品"记录在 `data\delivered.json`（其它账号是 `delivered.<账号>.json`，各账号互不干扰）。测试阶段想重新触发，删掉里面对应条目即可。
3. **发货内容**：在商品管理页的「发货内容」框里改就行，框里写多少发多少、写多行就发多行，发完内容还在，不需要补货；每次发货都记录在 `data\used_cards.log`（多账号时为 `used_cards.<账号>.log`）。
4. **系统消息文案**：如果真实付款后工具没反应，可能是闲鱼的实际系统文案变了（比如"买家已付款，等待卖家发货"）。打开聊天确认实际文字，把它加进 `trigger_keywords`（也可翻看 `logs\ws_frames.log` 里的原始消息）。子串匹配即可，`买家已付款` 能同时命中带后缀的完整文案。
5. **运行期间**浏览器要停在闲鱼"消息"页（工具会自动打开，正常情况不用管）。

## 风险提示

- 自动化操作闲鱼属于平台规则灰色地带，存在被风控、限制账号的可能。请保守使用：轮询别太密、发货延迟保留随机、单量不大时尽量人工确认。
- 本工具仅用于自动回复/发货你自己店铺的商品，请勿用于任何违规交易。使用产生的账号风险自负。
